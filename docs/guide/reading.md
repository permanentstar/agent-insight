# 证据等级与层次阅读

本书结论优先回答“当前代码做什么”，再解释它为什么这样组织。没有注释时必须沿构造、调用和写入点验证，不能用名词直觉补齐行为。

![从研究对象和基线逐层进入概念、请求链与边界](../assets/book-map.svg)

| 证据 | 能支持的结论 | 不能替代的部分 |
|---|---|---|
| source | 固定源码中存在的分支、调用、字段和写入顺序 | 实际成功运行、性能收益 |
| static-inference | 从调用链与状态约束推得的行为，明确标推断 | 上游作者动机、线上部署事实 |
| runtime | 命令、环境、输入和输出都有记录的观察 | 未测分支、其他平台、统计规律 |
| official | 官方规范、文档、changelog 或 commit 的说明 | 实现是否完全符合设计 |
| historical-document | 旧研究材料的转述 | 当前主干结论 |
| proposal | 本书作者提出的取舍或候选方案 | 已实现行为 |

自造术语先进入词典。每个术语注明所属层、白话含义、所有者、持久性、生命周期、关系和不等同的邻近术语。尤其不把进程对象、持久记录、一次调用、一个模型 turn 混为一谈。

每个深入小节使用以下定位格式：

| 当前位置 | 调用它的上层 | 它进入的下层 | 状态与副作用归属 | 返回总览 |
|---|---|---|---|---|
| 例如工具执行层 | agent loop 的工具批次调度 | tool.execute / provider | 参数、权限、结果与落库分别明确 | 链接本对象架构图 |

正文先解释成功主链路，再解释提前结束、取消、错误、崩溃和重试。重要边界用状态转移条件表补充图示；“没有核验”不是“不支持”。
