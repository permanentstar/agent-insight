# 每个对象的固定模板

这是面向学习者的问题模板，可拆为一套 Markdown，不要求每个问题独占文件。读者有基础编程知识，但尚不熟悉该 Agent。先用一个贯穿任务建立整体认识，再逐层解释概念和源码；各对象保留适合自身的讲解篇幅。

| 顺序 | 共同问题 | 必须交代 |
|---|---|---|
| 1 定位与学习目标 | 它解决什么问题，学完能解释什么？ | 应用/框架/内核的职责；本分册的贯穿任务；版本统一见前言 |
| 2 层次总图 | 一次任务跨过哪些层？ | 产品宿主、运行控制、模型/工具、上下文和存储的关系；先整体后局部 |
| 3 概念词典 | 哪些概念是理解主线的前提？ | 白话定义、所在层、owner、生命周期、持久性与相邻概念区别 |
| 4 构造与生命周期 | 这些对象如何准备好并协作？ | 组合根、创建/注入、长期对象与当次对象；结合任务说明复用 |
| 5 执行模式 | 默认怎样决策，能如何改变？ | 模型工具循环、ReAct、Plan & Execute 等；模式入口、支持方式、计划载体、执行与继续控制 |
| 6 一次任务 | 用户目标怎样成为实际动作和最终结果？ | 主流程/时序图、逐阶段输入输出、关键调用与必要源码；贯穿完整成功案例 |
| 7 主要状态与流程 | 哪些状态决定继续、等待或结束？ | 会话/运行/轮次/任务分层；真实状态图或控制流程图；状态转换条件与关键字段样例 |
| 8 非结构化信息与动态决策 | 文本如何进入模型，模型输出怎样进入程序？ | Prompt、消息、工具结果、记忆的组织；结构化 schema/事件/状态的转换；模型选择与程序控制的配合 |
| 9 上下文与历史 | 模型看到什么，保存的又是什么？ | 有代表性的请求样例、历史与投影、压缩前后变化、长期记忆；解释设计原因 |
| 10 工具与扩展 | 定义怎样接到本次执行？ | 发现、加载、激活、调用与反馈；权限和 hook 的主要生效位置；子 Agent 的组织方式 |
| 11 设计取舍与独有机制 | 为什么这样分层和组织执行？ | 适用任务、收益、代价；用相同任务比较备选方式；独有内容增加专题 |
| 12 主线补充与阅读自检 | 哪些分支会改变主要过程？ | 必要的继续/暂停/取消/恢复；细碎边界另附；自检问题与源码入口 |

执行模式、协作拓扑和持久性是不同维度。产品 Plan Mode 或计划清单不自动证明独立 Planner/Executor 架构；通用工具循环也不自动等同严格复现 ReAct 论文。每种模式通过实际入口、配置、提示词、路由和执行点说明支持程度。

模式也可以嵌套和组合：例如规划层组织多个步骤，某一步的执行器再使用模型工具循环。分析时交代各自所在控制层与交接数据，不把整个 Agent 强行归入单一标签。

图文配合解释同一段过程：总图说明所在层，局部流程/状态图说明走向，消息或状态样例说明数据如何变化。图后逐步解释原因；不只重复节点文字，也不把大段原始代码当教材。阅读自检要求读者复述一次任务、区分主要对象并找到关键调用，正文质量不以字数判断。

复制 [机制模板](mechanism.md) 深入每一章；比较章节采用 [比较模板](comparison.md) 的共同维度。名词不能在多个章节各自定义不同含义。导航、基线与 frontmatter 契约见 [维护契约](../maintenance/contracts.md)。
